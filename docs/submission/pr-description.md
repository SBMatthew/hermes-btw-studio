## Add `btw-studio` to the plugin catalog (Hermes Agent Plugin Hackathon entry)

Adds `plugin-catalog/btw-studio.yaml`, pinning `SBMatthew/hermes-btw-studio` (`v5.8.0`, `requires_hermes: ">=0.23.1"`).

**BTW Studio — side-channel `/btw` workspace, `$0` read-only SQLite session radar, and `Δτ` steer playbook for Hermes Agent.** `/btw` runs as a non-intrusive side channel alongside active Hermes turns: answers render as GitHub-Flavored Markdown (with inline media lightbox and DOM-confined snippet follow-ups) in a `33px` strip above the composer, a statusbar popover, a floating `PANES_AREA` window, or a studio dialog, while the main transcript and L0 prompt cache remain untouched (`ΔMainTranscript = 0 bytes`).

- **Mid-Turn Multimodal `/btw`, Opt-In Voice STT/TTS & `conversation_id` Continuity**: intercepts `/btw` in `COMPOSER_AREAS.middleware` carrying staged images, documents (`.pdf`, `.docx`, `.xlsx`, `.pptx`, `.ipynb`, `.sqlite`, `.zip`), pasted logs, `@session:<id>` context, user-triggered microphone dictation (`transcribe_btw_audio`), user-initiated local read-only `/btw` tools (`read_file`, `search_files`, `session_search`, `manage_connections`), and opt-in host tools (`ctx.dispatch_tool` for `image_generate`, `video_generate`, `vision_analyze`, `video_analyze`, `text_to_speech`, `web_search`, `web_extract`, `browser_exec`, off by default). Preserves `/btw` cards and probes across `/compress` compactions via Hermes `v0.23.1` `conversation_id` (`post_compaction`) and exposes `BTW_CONVERSATION_ID` via `ctx.register_session_env`. Works around #123202, #149380, and #129391 from the plugin surface and is complementary to core `ctx.side_question` (#143791) and open core PRs #130146, #119747, #125968, and #121178.
- **`$0` Read-Only Session Radar & Cross-Session Conflict Guard**: reads `state.db?mode=ro` (`PRAGMA query_only = ON`, tables `sessions`, `messages`, `session_turn_leases`, `async_delegations`) to surface context fill %, prompt-cache USD savings, AST/JSON syntax verification (`ψ-verify`), 10 deterministic Loop Guard detectors (`error_streak`, `command_loop`, `edit_churn`, `claimed_without_tool`, `unverified_edit`, `subagent_silent_failure`, `research_stall`, `cache_bust_warning`, `test_weakening`, `silent_model_fallback`, mapped to `INV`/`DOM` scope and `C3..C8` levers), and concurrent sibling sessions editing overlapping files/line ranges (`session_mesh_guard`).
- **Attached Action Dock & Subagents Fleet Hub**: attaches any diagnostic `/btw` card to draft or dispatch `session.steer` / `subagent.steer` with a 3-tier `ComposerModelPicker`, and supervises delegated child subagents via public `ctx.subagent_lifecycle` with a bounded 32/24/16 KB 3-accordion specialist dossier (`32 KB` Output, `24 KB` CoT & Tools, `16 KB` Prompt) plus post-completion `/btw` follow-ups.
- **Label-Free Harness² `Δτ` Contrast, `BTW.md` Playbook & 6-Axis Reading Lens** (after Xu et al., `arXiv:2610.14224`): evaluates the 3 tool calls after a steer (`helped`, `self_recovered`, `hurt`, `no_observed_effect`, `confounded -> NO_ENTRY`) via behavioral contrast, compiles verified rules into `BTW.md` (`1K-Step Capacity Slider` from `1K` to `16K` with rollback backup) and `btw-skills/` (reconciled read-only with `$HERMES_HOME/logs/curator/*/run.json` and `$HERMES_HOME/skills/.archive` on `post_curator_run`), and formats `/btw` output via a 6-Axis Independent Reading Lens (`[0,1]^6`, with `6D Hexagon`, `5D Polygon`, and `3D Triad` projections across `Visual`, `Monothread`, `Epistemic`, `Deep`, `Concise`, and `Structure`, including `🧩 Systematic ASD` and `🧬 AuDHD 3e`) paired with a procedural SVG telemetry companion (`compression_radar` alerts at `>= 75%` context fill and opt-in `BtwAerialMascotFlight`).

### How it differs from listed plugins (Rule 16)
Independent architecture — not a fork or skin of any bundled or listed plugin, and shares zero code with them:
- **vs. Core `/btw` (#123202, #149380, #129391), Open Core PRs (#130146, #119747, #125968, #121178) & `ctx.side_question` (#143791)**: Core's `ctx.side_question` issues one shared 60s **post-turn** lease (`post_llm_call`) for automated text-only follow-ups, returns `None` on subagents (`_delegate_depth > 0`), and deep-copies `messages`/`tools` every turn when granted; open PR `#121178` modifies `electron/main.ts` and `preload.ts` to open a separate text-only OS window. `btw-studio` does not request `llm.side_question` and touches zero Electron main-process files: it intercepts `/btw` in `COMPOSER_AREAS.middleware` inside `@hermes/plugin-sdk` to answer interactive user questions **mid-turn while tools run**, across live or finished **subagents**, and with **multimodal attachments** via `ctx.llm` + `state.db?mode=ro` (`ΔMainTranscript = 0 bytes`, zero `deepcopy`).
- **vs. `quote-ask`, `hermes-quote-to-chat`, `hermes-action-bar`, `prompt-snippets`, `study-tree`, `session-ref` & `you-should-know`**: `quote-ask`, `hermes-quote-to-chat`, and `hermes-action-bar` listen to global `document` selections across the main transcript to paste quotes, stage quote cards, or trigger static `llm.oneshot` popups; `btw-studio` registers **zero** global transcript selection listeners (`.btw-selection-toolbar` checks `proseRef.current.contains(...)` strictly inside its own `/btw` cards, and its `COMPOSER_AREAS.contextMenu` entry runs only inside the composer textarea where quote plugins opt out). Unlike `prompt-snippets` (static main-chat templates), `study-tree` (`session.branch` + `transform_llm_output` + 4 tools), `session-ref` (main-prompt `@session` text), and `you-should-know` (up to 5 automatic LLM calls/turn), `btw-studio` never branches sessions, never mutates main replies, interpolates live session tokens and `@session:<id>` inside `/btw` at `$0`, and runs zero background LLM calls on telemetry events.
- **vs. `perf-hud`, `hermes-context-overview`, `token-cost-meter`, `radar`, `flightdeck`, `local-fleet`, `weft`, `git-review`, `agent-station`, `protean-subagent-viewer`, `olympus`, `taskwatch` & `load-lock`**: `perf-hud`, `hermes-context-overview`, and `token-cost-meter` show passive numeric token/cost/TPS counters without reading tool outputs or steering; `radar` (#153619) is a multi-profile bot monitor with OS PiP and `SIGTERM` stop (zero hooks); `flightdeck` and `local-fleet` monitor/fail-over external vLLM/Ollama servers; `weft` requires `npx @celador/weft`, Git worktrees/hooks, 2 agent tools, and an external gateway (macOS/Linux only); `git-review` reviews git diffs; `agent-station` and `protean-subagent-viewer` are read-only viewers; `olympus` manages multi-profile cron/Kanban queues; `taskwatch` tails `terminal(background=true)` shell jobs (`process.list`); and `load-lock` brokers machine CPU/RAM permits via a Node daemon and 19 `load_lock_*` shell tools. `btw-studio` exposes **zero** agent tools (`provides_tools: []`), spawns no daemon, `git` subprocess, or shell commands, never reads `process.list`, works cross-platform, and pairs `$0` `state.db?mode=ro` diagnostics (10 Loop Guard detectors, `ψ-verify` AST checks, and `session_mesh_guard` concurrent file/line overlap detection) with live `session.steer` / `subagent.steer` and post-completion `/btw` subagent Q&A.
- **vs. `bhived`, `harness2`, `learnloop`, `dreaming`, `skill-court`, `skillens`, `hermes-memory-pane` & `hermes-memory-ui`**: `bhived` syncs cross-user lessons to `mcp.bhived.ai` (`BHIVED_API_KEY`) via `npx bhived-mcp`; `harness2` (#149360) registers 9 tools and clones profiles to run 4 full CLI subprocesses per trial; `learnloop` (#153821) runs interactive human study lessons via 8 tools and `transform_llm_output`; `dreaming` (#153828) registers a `MemoryProvider` wiki consolidator; `skill-court` runs Docker/Podman replay trials with paid LLM judges; `skillens` injects `pre_llm_call` skill-step nudges; and `hermes-memory-pane` / `hermes-memory-ui` wrap or inspect memory stores. `btw-studio` is 100% local (`ctx.state.data_dir/BTW.md`) with zero MCP/npm/cloud servers, profile cloning, containers, middleware, or judge spend — scoring steers online over the next 3 tool calls in `state.db?mode=ro` at `$0` (`helped`, `self_recovered`, `confounded -> NO_ENTRY`) and touching `MEMORY.md` only on explicit `memory_md_sync_mode` opt-in.
- **vs. `check-please`, `precog`, `promise-keeper`, `tldr`, `hermes-sanctuary`, `mascot-guide`, `pugin`, `kin`, `hermes-sidepulse`, `gemini-live` & `enchanted-composer`**: All 12 hooks return `None` — `btw-studio` never edits replies in `transform_llm_output` or re-prompts via `pre_verify` (`check-please`), never rewrites/blocks commands in middleware (`precog`, `promise-keeper`), never drops exit codes (`tldr`), needs no iframe worlds (`hermes-sanctuary`), external Electron/socket apps, OCR screenshots, or global `hermes config set` edits (`kin`, `hermes-sidepulse`, `mascot-guide`, `pugin`), and scopes opt-in STT/TTS/wake-word (`false` by default) strictly to `/btw` queries via host providers rather than cloud voice calls driving main turns (`gemini-live`, `enchanted-composer`).
- **vs. Bundled `plugins/hermes-achievements` (Rule 15)**: Not a fork or skin of the always-on Dashboard achievements tab; Playbook Milestones (`gamify_enabled: false` by default) render only inside BTW Studio's Settings/Learn view when opted in and count 12 side-channel playbook metrics (`BTW.md` rules, `Δτ` helped steers, `/btw` cards).
